# Производительность шага симуляции

Задача T38: довести шаг 256×256 до 50 мс и 300 МБ памяти. Цель по времени
**не достигнута**; ниже — замеры, что сделано и почему дальнейший выигрыш
требует смены представления данных.

## Методика

- Карта 256×256 (65 536 тайлов), 3 фракции, `seed=42`.
- Полный набор правил этапа 4: экономика, добыча, армия, экспансия,
  население, социум, культура, войны, торговля, дипломатия.
- Время — `time.perf_counter()` вокруг `engine.step()`; память —
  `tracemalloc` во время шагов (без генерации мира).
- Окружение: Windows, Python 3.12.4, CPython, pydantic 2.14.

Воспроизведение:

```bash
WORLDSIM_BENCH=1 pytest tests/benchmarks/test_step_benchmark.py -s
```

## Результаты

| Вариант | Время шага | Пик памяти |
| --- | --- | --- |
| До оптимизации (полные правила) | 26,6–29,5 с | 892 МБ |
| После оптимизации (полные правила) | 2,9–3,6 с | 211 МБ |
| Подмножество из 8 правил | ~2,3 с | — |
| Цель T38 | ≤ 0,05 с | ≤ 300 МБ |

Время улучшено примерно в 8 раз, память — примерно в 4 раза. Цель по
памяти достигнута, цель по времени — нет.

## Что сделано

1. **Быстрый путь применения изменений.** Внутри шага движок больше не
   вызывает `WorldState.evolve` для каждого правила: это приводило к
   `model_dump` + полной перевалидации 65 536 тайлов на каждое правило.
   Теперь состояние собирается через `model_copy`, а тайлы — через
   `_copy_tile` (копия `__dict__` с изменёнными полями).
2. **Проверка диапазонов без pydantic.** Для изменяемых полей тайла
   добавлен дешёвый контроль (`population ≥ 0`, `fertility`/`happiness`/
   `unrest`/`urbanization` в 0–100, `assimilation` в 0–1 и т.д.). При
   нарушении вызывается `RegionData.model_validate`, чтобы сохранить
   `ValidationError` для некорректных правил.
3. **Индекс владений в экспансии.** `ExpansionRule` строит множество
   тайлов фракции один раз за шаг вместо полного сканирования карты для
   каждой фракции.
4. **Кэш метрик на шаг** уже существовал (`StepContext.stats`): метрики
   считаются один раз и переиспользуются правилами.

## Почему 50 мс не достигнуты

- Шаг — это 20 правил, каждое проходит по 65 536 тайлам; даже 10 мкс на
  тайл дают ~13 секунд на все проходы.
- Доменные модели — замороженные pydantic-объекты (ADR 0002). Массовое
  обновление 130+ тысяч тайлов за шаг требует создания новых объектов и
  копирования словарей; это основной оставшийся расход.
- Соседство тайлов вычисляется на лету (`WorldMap.neighbors`) сотни тысяч
  раз за шаг.
- Чтобы получить 50 мс, нужен колоночный numpy-представление состояния
  (население, счастье, недовольство и т.д.) и векторные правила с
  синхронизацией в pydantic только на границе шага. Это меняет контракт
  `Rule.apply(state, ctx)`, ADR 0002 и все 20 правил; в рамках T38 такой
  редизайн не выполнялся, чтобы не рисковать детерминизмом и
  корректностью.

## Что дальше

- Колоночное представление тайлов с numpy и материализацией в
  `WorldState` раз в шаг.
- Кэш соседей на карту (предвычисленные id вместо вызовов `neighbors`).
- Пакетный API правил: правило возвращает массивы изменений, движок
  применяет их одной операцией.
- Профилировать на Linux/CI: абсолютные числа зависят от машины, но
  соотношение «20 правил × 65k тайлов» сохраняется.
